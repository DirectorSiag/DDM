Avances  -  PF  TESTING::  FCDECO:  
Hoy  DDM  asume  que  todo  mensaje  binario  recibido  es  DCL  CONC.  
El  flujo  actual  es:  
1.  MessageRouter  recibe  un  datagrama.  2.  Si  el  datagrama  empieza  con  "{"  y  termina  con  "}",  lo  trata  como  JSON.  3.  Si  no  parece  JSON,  lo  manda  directamente  a  DclConcController.  4.  DclConcController  solo  verifica  que  tenga  al  menos  3  bytes.  5.  Si  tiene  3  bytes  o  más:  
●     extrae  número  de  secuencia,  ●     envía  ACK,  ●     toma  el  payload  desde  el  byte  3,  ●     invierte  los  bits,  ●     lo  pasa  a  ConcDecoder:  Su  función  es  de  intermediario  de  protocolo,  recibe  el  
datagrama
 
crudo,
 
responde
 
al
 
emisor,
 
limpia/prepara
 
el
 
payload
 
y
 
recién
 
ahí
 
se
 
lo
 
entrega
 
al
 
decoder.
 
El  problema  es  que  “no  es  JSON”  no  significa  necesariamente  “es  DCL  CONC”.  
También  podría  ser:  
●  AND1  ●  AND2  ●  LPD  ●  ACK  ●   un  paquete  corrupto  ●   otro  mensaje  binario  del  protocolo  
Entonces,  si  llega  cualquier  mensaje  binario  de  3  bytes  o  más,  el  código  actual  puede  
responder
 
con
 
ACK
 
como
 
si
 
fuera
 
DCL
 
CONC.
 
Lo  ideal  sería  validar  primero  los  campos  de  protocolo:  
●  Device  Address  ●  flag  ACK/MSJ  ●  número  de  secuencia  ●  tamaño  del  mensaje  
Según  la  documentación:  
-  0x01  =  Pedido  DCL  CONC  -  0x04  =  DCL  CONC  -  0x02  =  AND1  -  0x03  =  AND2  -  0x00  =  LPD

Resumen:  
Hoy  DDM  asume  que  todo  binario  es  DCL  CONC.  
Eso  funciona  si  solo  llegan  mensajes  DCL  CONC,  pero  qué  pasa  si  empiezan  a  llegar  otros  
mensajes
 
binarios
 
del
 
protocolo?
 
Preguntarle
 
a
 
Cris
 
 
es  un  puerto  que  solo  recibe  eso,  de  todas  maneras  probar.  
Entonces  deberíamos  testear:  
●  AR-TDC  falso  ->  envía  DCL  CONC  ●  DDM  ->  responde  ACK  ●  DDM  ->  decodifica  payload  con  concDecoder  ●  ¿Qué  pasa  si  llega  AND?  ●  ¿Qué  pasa  si  llega  ACK?  ●  ¿Qué  pasa  si  llega  un  binario  con  Device  Address  incorrecto?  ●  ¿Qué  pasa  si  llega  un  DCL  CONC  de  tamaño  incorrecto?  
Quizás  tenemos  que  asumir  que  el  controller  ya  funciona  bien,  ahí  testeamos  solo  del  
decoder.
